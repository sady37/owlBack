6. self_contradiction 观察窗

代码：Engine.Tick() 内 · engine.go:271

非对称设计（review fix P0-1）：
self_contradiction 仅作用于 occupied 方向翻转。

原因：occupied 是"正向维持态"，需要持续证据喂养（HR/RR），翻转后短窗内 score 应保持高位，否则视为冲动翻转 → rollback。
vacant 是"默认安全态"，无需任何信号维持。leave 证据自然老化（score -80 → -30 → 0）是"证据老化"而非"自相矛盾"。
若对 vacant 也检查，会出现 "死亡交叉"：score 衰减跨过 -require_sustain_at 阈值即假触发 rollback，把空房间翻回 occupied —— B2B 护理场景的"幽灵床位"污染。

纠错路径：真"误报 vacant"由后续 enter 证据自然翻回，不靠 self_contradiction。

7. 具体场景走 trace

场景 A：sleepace InBed → 5s 后 sleepace LeftBed

t=0 Apply{Source:sleepace, Kind:enter, Ts:0} scorer: enterStrength=90, enterLatchUntil=10000ms leaveStrength cleared (no-op, was 0) score: decay(90,0) − 0 = 90 SM: 90 ≥ 50 prev=vacant → FLIP occupied emit bed:occupied subset_invariant → room:occupied 一并 emit t=5000 Apply{Source:sleepace, Kind:leave, Ts:5000} scorer: nowMs=5000 < enterLatchUntil=10000 → REJECTED (accepted=false) bed 保持 occupied ★ 厂家权威 latch 起作用

场景 B：sleepace InBed → 11s 后 sleepace LeftBed（latch 已过）

t=0 InBed: 同场景 A bed → occupied, room → occupied t=11000 LeftBed scorer: 11000 > enterLatchUntil=10000 → OK leaveStrength=80 (small_bed sleepace) ★ clear enterStrength = 0, enterTs = 0 score: decay(0,_)=0 − decay(80, 0)=80 → −80 SM: hysteresis 自 t=0 到 t=11000 已过 3s → OK −80 ≤ −50 prev=occupied → FLIP vacant emit bed:vacant

场景 C：HR/RR 持续顶住"厂家撒谎"

t=0 InBed → flip occupied t=29000 sustain (HR/RR present) scorer: sustainStrength=80, sustainTs=29000 t=30000 LeftBed scorer: ✓ latch 过 (11000+5000=16000 < 30000) ✓ leaveStrength=80, leaveTs=30000 ★ clear enterStrength=0 (但保留 sustain！) score: enterEff = 0 sustainEff = 80 (age=1s < 10s, fresh) pos = max(0, 80) = 80 bonus: sustainEff>0 AND lastEnterEventTs=0 still in window 60s BUT lastEnterEventTs 在 leave 时未被清 → age=30s < 60s → bonus +15 pos = 80 + 15 = 95 neg = 80 score = 95 − 80 = 15 SM: 15 in band (-50..+50) → no flip bed 保持 occupied ★ HR/RR 物理证据顶住 sleepace LeftBed t=40000 下一次 sustain 没来 (HR/RR 停) sustainTs=29000, age=11s > 10s → sustainEff=0 score: pos=0, neg=80 → −80 SM: −80 ≤ −50 → FLIP vacant ★ HR/RR 也停了才相信 sleepace 的 LeftBed

场景 D：radar InBed → 立即 sleepace InBed（同方向 max 非 sum）

t=0 radar Apply{Kind:enter} scorer: enterStrength=80 (radar) score: 80 → flip occupied t=100 sleepace Apply{Kind:enter} scorer: 同方向 max 检查 decay(80, 100ms) ≈ 80 (基本无衰减) 新 strength=90 ≥ 80 → 替换 enterStrength=90 lastEnterEventTs=100 (刷新) score: 90 (NOT 80+90=170) SM: hysteresis 3s 内 → no flip (已 occupied) ★ 同方向 evidence 取 max 非 sum，强源 win

场景 E：NumberPeople=3 直写不翻转

t=0 Apply{ZoneType:Room, Kind:count_change, Count:3} engine 路径: 命中 Kind=="count_change" 分支 直接 z.state.Count=3, UpdatedAt=now, LastSource="radar" 不经过 Scorer/StateMachine emit ZoneEvent{Transition:"count_change", NewState.Count=3} ★ 多人计数走旁路，独立于 occupied 状态机

场景 F：NumberPeople=0 不当作离开

t=0 Apply{ZoneType:Room, Kind:count_change, Count:0} engine 路径: 命中 Kind=="count_change" 分支 z.state.Count=0 occupied 状态不变（vacant 不会被翻转） ★ 设计意图：count=0 可能是"静止人/盲区/雷达漏检"，不能直接当 leave 如要让 count=0 触发离开，应由 adapter 额外发一条 Kind="leave" 证据， 且需要配套 yaml 配置该 source 的 strength（当前留空作为防误用）
