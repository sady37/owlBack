False Fall：Gate（生产）vs DBN Shadow

lost_track 误报治理 · 双轨架构与 DBN 进展 · 2026-06-03
一句话：当前真正在 fire 的是 gate-list（生产）——今天加固了 4 道闸 + 同房对账； DBN 是 shadow（只 log 不 fire），今天把"同房对账"也同构落进了 DBN 的 Track 层（TObsPeerLive）。 两条轨道逻辑同构、目的不同：gate 当下止血，DBN 为将来 cutover 替换 gate-list 备款。

0 · 问题：lost_track 为什么会误报

雷达跌倒判定里最难的一类是 lost_track（走动中目标突然消失 → 推断"可能倒地"）。 根本困境：真摔（人倒地、贴地弱回波丢锁）与 良性消失（走出门 / ghost 闪灭 / 站定被冻结 / 换 track-ID） 在雷达原始数据里几乎不可分——都是"track 没了"。

本会话所有修复的本质，是给"消失"这个事件补上它到底是哪种消失的判别证据。 问题在于：判别逻辑过去是一条条 if 手补在 adapter 里（gate-list），缺一个统一的隐状态信念层。

1 · 两条轨道并列

当前 Gate-list 生产 · 真 fire

位置：track_manager.go / bathroom_fall.go 里的离散守卫。

本质：≈100 条 if 规则，每条针对一类已知 FP 手补一个条件。

  • 命中即 取消 / 抑制 / 放行 lost-fall pending
  • 确定性、可单测、fixture 可回归
  • 缺点：规则之间无共享状态，打地鼠——新 FP 类型 = 新 if；多套时钟需要协调规则

DBN Shadow 影子 · 只 log

位置：belief/ 包 + belief_shadow.go 旁路。

本质：(Track × Room) 两层贝叶斯滤波，每帧 Predict+Observe，维护后验信念分布。

  • 每帧把 gate 的输入翻成观测喂进似然，跑 forward
  • 绝不 fire——把 DBN 判定 log 出来与 gate alarm 离线对账
  • 目标：等 shadow 证明与 gate 等价/更优，cutover 替换 gate-list
▲ 同一份输入，两套判定并行跑；用户只看到 gate 的 alarm，DBN 在日志里"陪跑"

2 · 核心差异：if 守卫 ↔ 转移概率

DBN 蓝图（doc/belief_dbn_completeness.md）的关键论断： 每一条打地鼠 gate，实质都是一条"缺失的隐状态转移"被手补成了 if。 把这些 if 内化成 DBN 的转移阵 / 发射 / 驻留，规则就不再相互打架——相反证据在同一个信念向量 b 上加权，贝叶斯自动仲裁。

3 · DBN 结构：为什么是两层

Track 层  T_t ∈ {None, Real, Ghost, JustLeft, Lost}      ← 今天主战场（P1）
            └ 自带转移阵 A_T + 由 verdict/几何/事件/缺测 发射驱动
            └ 回答"这条 blip 是真人/反射？在不在场？"——每条 track 自己的隐过程

Room  层  S_t ∈ {Empty, BedLying, BedRestless, Sit, StandWalk,
                 Fallen★, Transition, Left, Artifact}        ← P0 已落
            └ 9 态房间级姿态；Fallen 是唯一 fire Fall 的目标态
            └ 条件于 Track 层

每帧：  b ← normalize( diag(w^conf) · (Aᵀ · b) )
        Predict(A·b)  +  Observe(似然更新)；Conf=0 → 不更新（缺证据命门）

关键设计（model.go）：→Fallen 的转移概率刻意取极小（站走→倒 0.2，床上→倒 0.05）。 进 Fallen 的"灵敏度"全来自观测似然（firmware fall ×10 / kinematics ×8），不来自时间转移—— 否则缺证据期纯 Predict 会把信念慢慢渗进 Fallen，从沉默里凭空造跌倒（正是 CABB / John.Y 那类 FP）。

A_T：Track 层转移阵（今天的核心）

行=上一态，列=本态，值=相对倾向（行内归一）。红=进 Lost 的关键格，刻意压成 floor。

· Ghost→Lost = floor(0.1)：ghost 闪灭绝不变"丢失候选倒地"（method-2 结构化，靠状态记忆而非 if）。
· Lost 近吸收(80)：真人丢失不自愈；只有 recapture→Real / 门事件→JustLeft 等主动反证才出。
· absent 发射不区分 Lost vs None——谁是 Lost 谁是 None，只由消失前的 T 先验经 A_T 决定（Real 先验通 Lost，Ghost 先验通 None）。

今天新增的发射：TObsPeerLive

case TObsPeerLive:   // 同房（单床）对等雷达此刻见真人
    // → 房里那个真人是别台的 track，本 track 更可能是它的重影/重复，绝非独自倒地
    return tlk(map[TState]float64{
        TLost: 0.15,   // ↓↓ 强压"丢失候选倒地"
        TGhost: 2,     // ↑   偏向重影
        TNone:  2,     // ↑
        TReal:  0.5,
    })
单床闸在 adapter 把关（belief_shadow.go:205）：仅当 bedCount==1 && otherDeviceRealTrackRecent() 才发射此观测。 双床/双人病房不发——避免把另一位老人当"对等"误压（A 摔 + B 在场会变漏报）。 belief 模型只认观测，门控纪律留在 adapter，与生产 gate 的 bedCount==1 守卫同源。

4 · DBN 进展：从单层 HMM 到 (Track×Room) DBN + HSMM

P0 · Room 层单层 HMM shadow 已落
9 态 state.go + 转移阵 model.go + 似然 likelihood.go + forward belief.go。 gate→矩阵对照账本 belief_gate_to_matrix.md（≈100 条规则逐条映射）。Empty/Left 是第一类公民。
P1 · Track 层 T_t 隐链（A_T）本会话进行中 · 今天推进
补上"最大的那段缺失"——per-track 存在/真伪隐过程。belief/track.go 建成显式 HMM： 5 态 + A_T + 4 类观测（Present / Absent / Exit / PeerLive←今天）。 shadow 在 absent 扫掠按单床闸发射 TObsPeerLive。commit 0ddfcf9
P2 · 缺测发射 P(no-detect|s) + 可达退场 部分设计
"这帧没测到"本身带似然（贴地遮挡 vs 走出门 vs 空房）。 ObsReachableExit（丢失点近门+单帧可达→偏 Left 压 Fallen）已有观测种类， 文档 belief_p2_absence_emission.md。距离闸(#5)/id-swap(#6)待内化。
P3 · HSMM 驻留时长 未开工
lost ramp / confirmMs=90s / still-fall 时长门 / MovingPreconditionMs=60s 全是驻留时钟。 HMM 的几何分布装不下"维持数分钟才算真"，需半马尔可夫 HSMM 状态时长分布替代 ramp+timer。
Cutover · DBN 替换 gate-list 目标
等 shadow 在影子模式下证明与 gate 等价/更优（确定性角点 + fixture oracle 对账）， 再把 fire 路径从 gate-list 切到 DBN。对应 memory belief_state_rule_engine_reframe。
注意进展的真实边界：DBN 现在全程 shadow，一行都没 fire。 今天 false-fall 的真正止血全靠生产 gate（#1–6 那几道闸 + 同房对账）。 DBN 今天的进展 = 把第 4 道闸（同房对账）也补进了 Track 层，使 4 道主力闸在 shadow 里全部有了同构对应物—— 这是为 cutover 攒"能力齐套"的证据，不是把判定权交给了 DBN。
