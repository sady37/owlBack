## 4. 判据修正（重要）

**用户指出**：pose=1 缺失不能作为误报证据。

**原因**：雷达姿态分类是内部连续计算的，但 track 数据上报间隔 1 秒。跌倒的瞬时态 pose=1 持续时间通常 <1s，很容易落在两次上报之间被采样错过。真实跌倒出现 pose 序列 2/4 → 5（跳过 1）是完全可能的。

### 更可靠的判据组合

| 判据 | 本次数据 | 解读 |
|---|---|---|
| **z 坐标变化**：跌倒前后应有 z 从站/坐高度降到地面高度的痕迹 | z 全程为 0 | 强误报信号 |
| **x/y 位移**：真实跌倒常伴随短距离横向位移（通常 ≥30cm） | 漂移仅 10cm | 偏静态，倾向误报 |
| **过渡前姿态**：从站（4）跌倒更易识别，从坐（2）跌倒运动学特征与跌倒姿态相近，误判率高 | 过渡前 pose=2 稳定 10+ 秒 | 高误判风险场景 |
| **roomengine 区域语义**：结合地面高度/床位区域做二次验证 | 需 roomengine 支持 | —— |

### 修正后的结论

**仍倾向于误报**（低位姿态混淆），但**置信度比最初说的要低**：
- z 全程 0 + x/y 几乎无位移 + 过渡前静坐 10+ 秒 → 更像是"坐在低矮处被雷达重新分类为跌倒姿态"
- 最终定性需要 roomengine 的地面高度/床位区域信息

## 5. 与 AI-Fall 模型的关联（项目上下文）

另一个 agent 正在建立 AI-fall 模型，核心思路：

**用非跌倒状态下 z 值的正常变化特征，反向给 roomengine 的 cell 打空间语义标签**（床、沙发、椅子等可 lie 区域）。

### 工作原理

- 长期统计某个 cell 里 pose=1/2（躺/坐）且持续时间长、z 值稳定在某一高度的样本 → 该区域大概率是**床 / 沙发 / 椅子**
- 下次该 cell 触发 pose=5 时，若 z 值仍在"沙发高度"附近而非地面高度 → 高概率是**躺在沙发上被误判**，不是真跌倒

### 对本案例的意义

本次事件位置 (-40, 410) 长期稳定，过渡前有 pose=2（坐）持续 10+ 秒——**高度符合沙发/椅子区域的特征**。若 roomengine 已学习到该 cell 是沙发，则可直接抑制该跌倒告警。
