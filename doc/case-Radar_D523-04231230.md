- y 同步（反射不改变前后距离）
- canvas x 位于 Wall 左边界外（典型墙外 ghost）

## 4. Engine 识别 Ghost 的判据（从本数据提取）

### 房间几何上下文（关键先决条件）

根据 [layout-D523-demo.json](layout-D523-demo.json)：

```
Wall 房间多边形:  x ∈ [-250, 250], y ∈ [50, 550]
Radar 位置:       (-130, 50, 200)  wall 模式，高 2m
FOV 边界:         leftH=300, rightH=300, frontV=400, rearV=0
                  → 画布 FOV: x ∈ [-430, +170], y ∈ [50, 450]

实际可达域 = InRoom ∩ InFOV = x ∈ [-250, +170], y ∈ [50, 450]
```

### ★ 判据 0（最硬，几何上限）：**InRoom × InFOV 检查**

**Ghost 最直接的判据是"雷达理论上看不到这里"**——一帧一帧查 cell 位图即可：

| cell 位图状态 | 语义 | 对 track 的影响 |
|---|---|---|
| `InRoom && InFOV` | 理论可达 | 正常，参与 Real/Ghost 评分 |
| `!InRoom && InFOV` | **墙外但雷达看到** | **Ghost 强证据**（墙面多径反射）|
| `InRoom && !InFOV` | 房内雷达盲区 | 合法消失点；不该有 track 出生 |
| `!InRoom && !InFOV` | 完全不可能 | **直接判 Ghost，0 容忍** |

**p1 实测**（换算到 canvas）：
- 本地 x ∈ [110, 300] → **canvas x ∈ [-430, -240]**
- 本地 y ∈ [130, 420] → **canvas y ∈ [180, 470]**
- Wall 左边界 canvas x = -250
- FOV 左边界 canvas x = -430（Radar.X=-130, leftH=300）
- 比较：
  - p1 canvas x ∈ [-430, -240] 基本**全部 < -250** → **!InRoom（墙外）**
  - p1 canvas x 刚贴 FOV 左边（-430）→ **InFOV 仍为 true**

→ **p1 绝大多数帧属于 `!InRoom && InFOV` 单元**——**典型的"墙面反射 ghost"**（雷达能看到墙外但那里不是房间内部，物理上不可能有人）。

**engine 只需查 cell 位图（InFOV=true, InRoom=false）就能当场判 ghost**——不需要任何运动分析。

**这才是 ghost 最直接的判据——不是 z 锁死，不是 pose 贫乏，而是物理位置超出房间多边形**。

```go
// 最快捷的 ghost 判定（构建期 rasterize 后运行时只 O(1)）
cell := grid.CellAt(f.X, f.Y)
if cell == nil || !cell.InFOV {
    // 雷达报了一个它自己看不到的位置 = 强 ghost
    ts.AdjustScore(-30)
    grid.MarkGhostBirthOrTransit(f.X, f.Y)
}
if cell != nil && !cell.InRoom && cell.InFOV {
    // 墙外反射 ghost（典型多径）
    ts.AdjustScore(-20)
}
```

### 判据 1：**z 恒为 0** 是最强信号

| 指标 | p0（真人）| p1（ghost） |
|---|---|---|
| Walking z_σ | **33.6** | **9.4** |
| Standing z_σ | 40.0 | 6.1 |
| z==0 帧占比 | ~30% | **~95%** |

→ **N 帧内 z==0 的比例 > 80% → GhostDecay++**

### 判据 2：**双 track 运动相关 + 其中一方物理异常**

当两个 track 同时存在时，**不要死盯 x 镜像**——ghost 几何有多种形态：

| Ghost 类型 | x 关系 | y 关系 | 物理原因 |
|---|---|---|---|
| **镜像 ghost**（本 case）| x 符号相反 | y 同步 | 雷达→目标→侧墙→回来 的**多径反射** |
| **邻近 ghost**（其他场景）| x 接近 | y 同步 | 同一目标被**分裂**成两个 track（多普勒/相位混叠）|
| **锁死 ghost** | 位置恒定不动 | 位置恒定 | 反射热点 / 金属干扰 |

**统一规则**（不依赖几何关系）：

- 必要条件 1：两 track **运动高度相关**（`|Δy| < 30cm` 且 pose 状态变化时间相关）
- 必要条件 2：其中一方有**物理异常签名**：
  - `z` 恒 ≈ 0（σ < 10cm，而真人 Walking σ > 20cm）
  - `pose` 多样性低（只在 Walk/Stand 之间切换，无 Sit/Lie）
  - 位置过稳（σ=0 多帧）或位置跳跃（残差 > 200cm）

→ 物理异常的一方判为 ghost。

```go
// pseudo
func detectGhostPair(t0, t1 *TrackState) *TrackState {
    // 运动相关性检查
    yDiff := abs(t0.LastY - t1.LastY)
    poseCoherent := t0.RecentPoseChanges() == t1.RecentPoseChanges()
    if yDiff > 30 || !poseCoherent {
        return nil  // 不相关，不是 ghost 对
    }

    // 看谁物理更假
    ghostScoreT0 := scoreGhostLikeness(t0)
    ghostScoreT1 := scoreGhostLikeness(t1)
    if ghostScoreT1 > ghostScoreT0 + 10 {
        return t1
    }
    if ghostScoreT0 > ghostScoreT1 + 10 {
        return t0
    }
    return nil
}

// 基础 ghost 物理评分
func scoreGhostLikeness(ts *TrackState) int {
    score := 0
    // z 锁死
    if ts.ZLockedFrames > 5 { score += 30 }
    // pose 贫乏
    if ts.PoseVariety < 3 { score += 20 }
    // 位置过稳（完全不动 > 5 帧）
    if ts.SamePosFrames > 5 { score += 20 }
    return score
}
```

**为什么运动相关（而非几何关系）是判定核心**：ghost 总是**依附**于真人目标，雷达上不存在"独立 ghost"。所以只要两 track 运动联动，且一方物理指标假，就能抓到。

### 判据 3：**pose 状态贫乏**

p0 有 4 种 pose（Walk/Stand/Sit/SusSitGround），p1 只有 2 种（Walk/Stand）。

→ 长期只在 Walk/Stand 之间切换，从不出现 Sit/Lie → ghost 嫌疑 +

### 判据 4：**Kalman 残差不自然**

p0 Walking 位置 σ 50-90cm（合理的人类走动步幅）
p1 Walking 位置 σ 40-70cm（模仿 p0 但**z=0 不连动**）

→ 若 Kalman 位置残差合理但 z 恒 0，是典型 ghost

### 判据 5：**Birth cell 的 GhostRatio 累积**

p1 的出生位置（18:35:00 时 x=150, y=350）长期会积累 GhostDecay。新 track 出生在高 GhostRatio cell → 5 因子扣分。
