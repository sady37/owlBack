# 事件1：床上跌落检测 - 评估过滤逻辑详解

## 📋 概述

事件1用于防止人从床上跌落，但雷达因误差或干扰未报警。通过 Sleepace 离床事件触发，结合雷达数据综合判断。

---

## 🔍 前置过滤条件（第一层过滤）

在进入事件1评估之前，以下条件会直接过滤掉，**不进行评估**：

### 1. 卡片类型过滤
```go
if card.CardType != "ActiveBed" {
    return nil, nil  // 直接退出，不评估
}
```
- ✅ **通过**：`CardType == "ActiveBed"`（床位卡片）
- ❌ **过滤**：`CardType == "Location"`（门牌号卡片）或其他类型

### 2. 床状态数据过滤
```go
if realtimeData.BedStatus == nil {
    return nil, nil  // 直接退出，不评估
}
```
- ✅ **通过**：`BedStatus != nil`（有床状态数据）
- ❌ **过滤**：`BedStatus == nil`（无床状态数据，无法判断离床）

### 3. 立即退出条件（如果已回到床上）
```go
if realtimeData.Heart != nil || realtimeData.Breath != nil {
    return nil, nil  // 有HR/RR，说明人已回到床上，退出
}
```
- ✅ **通过**：`Heart == nil && Breath == nil`（无心率呼吸，可能离床）
- ❌ **过滤**：`Heart != nil || Breath != nil`（有心率或呼吸，人已回到床上）

## 📊 阶段1：建立 Lying 基线（准备阶段）

### 目的
为跌落检测建立可靠的参考基线。**仅在睡眠状态时记录**，不是简单的 lying 姿态。

### 记录时机
- ✅ **记录**：检测到**睡眠状态**（`SleepStage` 表示睡眠）
- ❌ **不记录**：非睡眠状态（清醒、坐着等）

### 记录内容
```go
type Event1State struct {
    LyingHeight   *float64  // lying时的高度值（作为参考值）
    LyingPosition *struct {  // lying时的位置
        X float64
        Y float64
    }
    LyingTime     *int64    // lying开始时间
}
```

### 关键逻辑
- **lying值仅作为参考值**，主要用于**确认跌落**，而不是否认跌落
- 如果高度降低了（`current_height < lying_height`），确认跌落
- 如果高度没降低，**不能否认跌落**（因为高度数据不可靠）

### 存储位置
- **Redis键**：`alarm:state:{card_id}:track_{track_id}:event1`
- **TTL**：5分钟（事件1的最长持续时间）

## ⚠️ 阶段2：跌落检测（T0触发）

### T0：触发条件
- **T0**：Sleepace 检测到离床事件（`bed_status == "off_bed"`）
- **记录**：`LeftBedTime = T0`（离床时间）
- **状态**：进入可疑跌倒检测流程

### 退出条件（持续检查）

在整个事件1过程中，**每次评估时都检查**以下退出条件，**任何时候满足就立即退出**：

#### 退出条件1：Sleepace 有 HR/RR
```go
if realtimeData.Heart != nil || realtimeData.Breath != nil {
    return true  // 退出事件1
}
```
- **含义**：人可能回到床上，Sleepace 检测到心率/呼吸
- **优先级**：最高（立即退出）

#### 退出条件2：Sleepace 有上床事件
```go
if realtimeData.BedStatus != nil && *realtimeData.BedStatus == "on_bed" {
    return true  // 退出事件1
}
```
- **含义**：Sleepace 明确检测到人回到床上
- **优先级**：最高（立即退出）

#### 退出条件3：Radar 检测到在移动

## ⏰ 时间点检查（定时检查）

### T0+10秒：危险情况检测（提前触发）

#### 检查条件
1. **track_id 突然消失**
   - 之前存在的 `track_id` 在当前数据中消失
   - 没有改变位置，但突然消失

2. **30秒后未出现新的可移动 track**
   - 从 T0+10秒 开始监控
   - 如果 30秒内没有新的可移动 track 出现

#### 如果满足
- ✅ **立即报警**：`Fall`（AI-fall，**ALERT** 级别）
- **不等待** T0+120秒，提前触发

#### 逻辑说明
- 从 T0+10秒 开始监控 `track_id` 是否消失
- 如果消失且 30秒内没有新的可移动 track 出现，说明很可能是被遮挡或跌落了
- 比等到 T0+120秒 更及时，能更早发现危险情况
- **注意**：由于轮询间隔为 10秒，T0+10秒 可以确保在 10秒或 20秒时检测到，比 T0+5秒 更稳妥

---

### T0+60秒：可疑跌倒

#### 检查条件（T0+60秒时）
1. **60秒内没有退出**（退出条件未满足）
2. **睡眠板没有呼吸心率**（`Heart == nil && Breath == nil`）
   - Sleepace 已确认离床
3. **雷达仍显示相同 track 在床的区域**
   - `PersonCount > 0`
   - 存在 `track_id` 且 `area_id` 匹配床的区域

#### 如果满足
- ✅ **报警**：`SuspectedFall`（可疑跌倒，**WARNING** 级别）

#### 逻辑说明
- 给 60秒 观察窗口，如果 60秒内出现正常情况（有HR/RR、上床事件、移动），退出
- 如果 60秒后仍无正常情况，报可疑跌倒

---

### T0+120秒：确认跌倒（AI-fall）

#### 检查条件（T0+120秒时）
1. **120秒内没有退出**（退出条件未满足）
2. **身高值较床或之前的 lying 高度降低**
   - `current_height < bed_height` 或
   - `current_height < lying_height`（如果 `lying_height` 存在）
   - **注意**：lying值仅作为参考，主要用于确认跌落
3. **人未移动**（位置未变化）
   - 雷达仍显示在床区域
   - 位置变化小于阈值（需要历史位置数据）
4. **track_id 仍存在**（未消失）
   - `PersonCount > 0`
   - `track_id` 仍然存在

#### 如果满足
- ✅ **立即报警**：`Fall`（AI-fall，**ALERT** 级别）
- **报警位置**：在所在位置报

#### 逻辑说明
- 高度降低 + Sleepace 确认离床 + 人未移动 → 确认跌落

## 📝 关键逻辑点总结

### 1. 以 Sleepace 为准
- Sleepace 检测到离床且无心率/呼吸，基本确认人离床了
- Sleepace 有 HR/RR 或上床事件，立即退出

### 2. Radar 数据可信度低
- lying 是静止状态，Radar 不可靠
- 跌落检测时，Radar 显示在床区域可能是静止状态，不可靠
- 需要结合 Sleepace 数据综合判断

### 3. Lying 值的作用
- **仅作为参考值**，主要用于**确认跌落**，不用于否认跌落
- 如果高度降低了（`current_height < lying_height`），确认跌落
- 如果高度没降低，**不能否认跌落**（因为高度数据不可靠）

### 4. 退出机制
- 如果 Radar 检测到人离床且有移动，退出事件1
- 如果 Sleepace 有 HR/RR 或上床事件，立即退出

### 5. 危险情况优先
- track_id 突然消失且 30秒内未出现新的可移动 track，即刻报警
- 不等待 T0+120秒，提前触发
- **时间点选择**：T0+10秒（而非 T0+5秒），因为轮询间隔为 10秒，T0+10秒 可以确保在 10秒或 20秒时检测到，更稳妥

## 📊 数据依赖

### 输入数据（RealtimeData）
- `BedStatus`：床状态（必需）
- `Heart`：心率（可选，用于退出条件）
- `Breath`：呼吸率（可选，用于退出条件）
- `SleepStage`：睡眠状态（用于阶段1）
- `PersonCount`：人数
- `Postures`：姿态列表（包含 `tracking_id`）
- `Timestamp`：时间戳

### 状态数据（Event1State）
- `LyingHeight`：lying 时的高度值
- `LyingPosition`：lying 时的位置
- `LyingTime`：lying 开始时间
- `LeftBedTime`：T0（离床时间）
- `TrackID`：跟踪的 track_id

### 外部数据（需要查询）
- `bed_height`：床的高度（用于 T0+120秒 检查）
- `area_id`：床的区域ID（用于 T0+60秒 检查）
- 历史位置数据（用于位置变化检测）
