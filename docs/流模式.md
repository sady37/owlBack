## wisefido-sleepace 2.0 改造提要

### 已完成：owl-common/observation 包

三个文件定义了全系统统一的数据协议：

- **`domain.go`** — 7 个业务域: Vital, Motion, Track, Device, Status, Event, Command。每个域对应一个 Flag 位 (0x01-0x40)。
- **`fields.go`** — 全量字段注册表 (Registry)。所有 gateway 必须使用这些标准 key，禁止自定义。包含 FieldDef{Key, Type, Unit, Domain, Persist, Min, Max, Enum}。
- **`message.go`** — 统一消息结构: Header{UnitID, CardID, DeviceID, Timestamp, Flags} + Data{map[string]any}。含 Validate()、ToStreamMap/FromStreamMap、IsData/IsEvent 路由判断。

### 待做：wisefido-sleepace 网关改造

**目标：** 将 `mqtt_consumer.go` 中的 dispatch 逻辑改为使用 `observation.Message`，发布到两条流。

**核心原则：Gateway = 哑管道（协议翻译器）**
- 不做阈值判断、不做报警使能过滤
- 只负责：Sleepace MQTT 格式 → observation 标准字段 → Redis Stream

**两条输出流：**
- `iot:monitor:stream` — Flags 含 Vital/Motion/Track/Device 的消息
- `iot:event:stream` — Flags 含 Status/Event/Command 的消息

**dataKey 到新模型的映射：**

| dataKey | 输出流 | 标准字段 |
|---|---|---|
| realtime | monitor | heart_rate, respiratory_rate, body_move, turn_over, sit_up, left_right, bed_status, init_status, signal_quality |
| connectionStatus | event | online |
| sleepStage | event | sleep_stage, left_right |
| inBedStatus | event | bed_status, left_right |
| deviceSenSor | event | device_failure |
| pressureSenSor | event | detached |
| alarmNotify | event | event_id, event_name, event_status, event_level, event_since, event_reason |
| upgradeProgress | event | cmd_action("firmware_upgrade"), cmd_progress |
| analysis | 无流输出，触发 reportService.DownloadAndSave |

**需改造的文件：**
1. `internal/consumer/stream_publisher.go` — 用 `observation.NewMessage()` + `ToStreamMap()` 替换当前的自由格式 map，只保留 `PublishMonitor` 和 `PublishEvent` 两个方法
2. `internal/consumer/mqtt_consumer.go` — dispatch 中每个 case 改为构造 `map[string]any` 用标准字段 key，调用新的 publisher
3. `internal/service/card_mapping.go` — 提供 UnitID/CardID 查询，供构造 Header 时填充

**注意事项：**
- realtime 消息包含跨域字段（Vital + Motion + Status + Device），Flags 自动计算。按 IsData() 判断走 monitor 还是 event。但 realtime 含 bed_status/init_status 属于 Status 域，IsData() 会返回 false。**需决策**：拆分 realtime 为纯数据部分和状态部分分别发送，或把 bed_status/init_status 从 realtime 消息中剥离，单独走 event。
- 设备原生报警（alarmNotify）透传到 iot:event:stream，由 cardagg 统一做使能过滤和去重。
- `statusTracker` 保留，用于 HTTP API 返回设备即时状态，不影响流架构。
